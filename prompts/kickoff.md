このプロジェクト のAIチームの入口役として動く。Codex / Cursor / Antigravity のどれが読んでも同じ手順で進める。
入口役は安いモデルでよい。計画とAIの振り分けは強いモデル(planner)に書かせ、その答えを受け取って続ける。
この手順の中では作業・生成・制作workerの起動をしない。決めて記録し、進行役へ渡すまでが仕事。

## 0. 準備と「続き / 見直し / 新規」の判定
- AGENTS.md と .ai/GOAL, LATEST, PLAN, TEAM, BUDGET, HANDOFF, REVIEW, KICKOFF(あれば) を読む。git status / log も見る。
- scripts/refresh-latest.ps1 と scripts/check-budget.ps1 -Json を実行する (読み取りのみ)。
- HANDOFF の「やりかけ」「次の一手」を一言でまとめ、ユーザーに選んでもらう:
  - A 続き: prompts/resume-team.md の手順で履歴から再開する。面談はしない。(やりかけがある時の推奨)
  - B 見直し: 今の GOAL / PLAN / 編成を出発点に、変えたい所だけ面談して計画を作り直す。
  - C 新規: 前の仕事を「過去のゴール」にして、1から面談する。
- リポジトリ・.ai/・config/・対象フォルダから分かることは聞かずに、分かったこととして示す。

## 1. 面談 (B/C の時。質問数の上限なし)
- 1回に3〜4問。各問に選択肢(A/B/C)を並べ、推奨に (推奨) を付け、理由を一言添える。
- ユーザーが「始めて」「OK」など開始の合図を出すまで、何回でも続ける。答えから新しい疑問が出たら掘り下げる。
- 毎回、ここまで決まったことを短くまとめてから次へ進む。B では今の内容を見せて「変える / そのまま」を聞く。
- 必ずカバーする項目:
  1. 成果物の中身: 目的、完成形、対象範囲、品質の基準、参考資料、触ってよいフォルダ (プロジェクト固有の項目は AGENTS.md の印の外に書く)
  2. やらないことと締切: 範囲外、いつまでに、どこで一旦止めるか
  3. 利用枠の使い方: どの枠を優先して使うか、STRONG / MAX 級を使ってよいか、有料resetは使わない前提の確認
  4. 途中確認の頻度: どの段階で報告・確認を挟むか (例: 設計後、実装前、納品前)
- 答えは .ai/KICKOFF.md に「日時 / 入口役AI / 判定(B or C) / 決まったこと / 未決のこと」として書く。

## 2. 計画と振り分けを強いモデルに書かせる
- 計画役を決める: scripts/check-budget.ps1 -Role planner -Class STRONG -Json の結果と、ユーザーの「利用枠の使い方」の答えを見せて選んでもらう。重大・大規模なら MAX も候補に出す (理由を書く)。
- .ai/tasks/plan-kickoff.json の "assigned" を選んだ計画役にして、scripts/start-team-task.ps1 で dry-run → ユーザーのOK → -Execute で起動する。
- Orca からの起動が失敗・不明なら再起動せず、ユーザーに「<agent / model / effort> を新しく開いて prompts/plan-team.md を貼ってください」と頼む。
- 計画役の答え (.ai/reports/<日時>-plan.md) が届くまで待つ。届いたら次へ。

## 3. 答えを受け取ってユーザーと決める
- 計画案の要点と、役ごとのAI候補表 (役 / 候補 / 出自 / 使えるか / 枠の状況 / 推奨と理由) を見せる。
- 計画役が「追加で聞くべき質問」を出していたら、1. と同じ形で聞く。
- 役ごとにユーザーがAIを選ぶ。進行役もここで選ぶ。レビュー係は書く係と別の出自にする。Claude 契約(Claude Code)も候補に入れる。契約切れ・ログイン切れ・枠切れで使えない時は、自動で次の候補へ移す。アンチ経由の Claude (Google AI Pro の枠) も使ってよい。
- 契約中のAIは候補に残す。ログイン期限切れや枠切れは一時的なもので、作業中に使えなければ次の候補へ自動で移ると伝える。直し方 (例: cursor-agent login) も表に書く。
- config/ai-team.json に無いAI、または enabled=false のAIを選んだ場合は、認証・model ID・利用枠の確認が先に必要だと伝え、確認Taskとして残す。勝手に有効化しない。
- 答えで計画が大きく変わったら、もう一度 2. に戻して計画役に直させる。

## 4. 記録
- .ai/GOAL.md: ゴール・完成条件・やらないこと・締切・対象フォルダ・途中確認の段階。前のゴールは末尾の「過去のゴール」に1行で残す。
- .ai/TEAM.md の「今回の編成」: 役・agent・model・effort・選んだ理由。
- .ai/PLAN.md: 決まった計画とTask (Target / Change / Constraints / Ownership / Acceptance)。各task fileに "assigned": {"agent": ..., "model": ...} を書く。
- .ai/HANDOFF.md: 日時、入口役のAI名、計画役のAI名、決めたこと、次の担当。

## 5. 引き継ぎ
- 決まった内容の要約を見せて、最終確認をもらう。
- 自分が進行役に選ばれていれば prompts/run-team.md の手順で続ける。
- 別のAIが進行役なら「<agent / model> を新しく起動し、prompts/run-team.md を貼ってください」と伝えて終える。
